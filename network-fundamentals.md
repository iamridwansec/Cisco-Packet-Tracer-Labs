# 3.1 The OSI Reference Model

## Definition

The **Open Systems Interconnection (OSI) Model** is a conceptual framework developed by the **International Organization for Standardization (ISO)** to standardize how devices communicate over a network.

The model divides network communication into **seven logical layers**, where each layer performs a specific function and communicates with the layers directly above and below it.

The OSI model helps engineers:

- Understand network communication
- Design interoperable systems
- Troubleshoot network problems
- Identify where failures occur
- Learn networking in a structured way

---

## Purpose of the OSI Model

The OSI model exists to:

- Standardize network communication.
- Allow equipment from different manufacturers to work together.
- Simplify troubleshooting.
- Separate networking functions into manageable layers.
- Make network design modular and scalable.

---

## The Seven Layers of the OSI Model

| Layer | Name | Primary Function | Data Unit |
|--------|------|------------------|-----------|
| 7 | Application | Provides network services to user applications | Data |
| 6 | Presentation | Formats, encrypts, and compresses data | Data |
| 5 | Session | Establishes, manages, and terminates sessions | Data |
| 4 | Transport | Provides reliable or unreliable delivery | Segment / Datagram |
| 3 | Network | Determines logical addressing and routing | Packet |
| 2 | Data Link | Uses MAC addresses and frames for local delivery | Frame |
| 1 | Physical | Transmits electrical, optical, or wireless signals | Bits |

# 3.2 The TCP/IP Model

## Definition

The **TCP/IP Model** is the practical networking model used on modern IP networks, including the Internet. It defines how data is packaged, addressed, transmitted, routed, and received.

Unlike the seven-layer OSI model, TCP/IP groups functions into **four layers**.

| TCP/IP Layer | Equivalent OSI Layers |
|--------------|-----------------------|
| Application | OSI Layers 5–7 |
| Transport | OSI Layer 4 |
| Internet | OSI Layer 3 |
| Network Access | OSI Layers 1–2 |

---

## Why TCP/IP Is Important

TCP/IP is used by:

- The Internet
- Enterprise Networks
- Cloud Providers
- Data Centers
- Home Networks
- Cisco Equipment

It is the protocol suite you'll configure throughout your Packet Tracer labs.

---

# 3.3 Encapsulation

## Definition

Encapsulation is the process of adding protocol information to data as it moves **down** the networking stack before transmission.

Each layer adds its own header (and sometimes a trailer), creating a complete unit for transmission.

### Encapsulation Flow

```text
Application Data
      ↓
Transport Segment
      ↓
Network Packet
      ↓
Data Link Frame
      ↓
Physical Bits
```

---

# 3.4 Decapsulation

## Definition

Decapsulation is the reverse of encapsulation.

As data arrives at the destination, each layer removes the information that was added during encapsulation until the original application data is delivered.

---

# 3.5 Data Transmission Methods

Network communication can occur in three primary ways.

## Unicast

One sender communicates with one receiver.

Example:

One computer sending an email to another computer.

---

## Broadcast

One sender communicates with every device on the local network.

Example:

ARP Request

---

## Multicast

One sender communicates only with devices that have joined a specific multicast group.

Example:

Live video streaming.

---

# 3.6 Network Communication Process

A simplified communication process is:

1. User creates data.

3. Data is encapsulated.
4. Frames are transmitted.
5. Switch forwards frames.
6. Router forwards packets (if needed).
7. Destination receives data.
8. Data is decapsulated.
9. Application displays the information.

# Stage 3A – Ethernet & MAC Addressing

> Ethernet is the most widely used technology for communication within Local Area Networks (LANs). This section explains how Ethernet works, how devices identify one another using MAC addresses, and how switches forward data between devices.

---

# 3A.1 What is Ethernet?

## Definition

Ethernet is a family of wired networking technologies defined by the **IEEE 802.3** standard. It specifies how devices communicate over a Local Area Network (LAN), including how data is formatted into frames and transmitted across physical media such as copper or fiber-optic cables.

Ethernet is the dominant LAN technology used in homes, businesses, schools, and data centers.

---

## Purpose of Ethernet

Ethernet provides a standardized method for:

- Connecting devices on the same LAN.
- Transmitting data reliably between devices.
- Defining frame formats.
- Controlling access to the transmission medium.
- Supporting high-speed communication.

---

# 3A.2 IEEE 802.3 Standard

Ethernet is maintained by the **Institute of Electrical and Electronics Engineers (IEEE)** under the **802.3** standard.

The standard defines:

- Frame format
- Cabling specifications
- Transmission speeds
- Physical signaling
- Error detection methods

Common Ethernet speeds include:

| Standard | Speed |
|----------|-------:|
| Ethernet | 10 Mbps |
| Fast Ethernet | 100 Mbps |
| Gigabit Ethernet | 1 Gbps |
| 10 Gigabit Ethernet | 10 Gbps |
| 40 Gigabit Ethernet | 40 Gbps |
| 100 Gigabit Ethernet | 100 Gbps |

---

# 3A.3 What is a MAC Address?

## Definition

A **Media Access Control (MAC) Address** is a unique hardware identifier assigned to a network interface card (NIC) by the manufacturer.

MAC addresses operate at **Layer 2 (Data Link Layer)** of the OSI Model.

Unlike IP addresses, MAC addresses are intended to uniquely identify a network interface on a local network.

---

## Characteristics

- 48 bits (6 bytes)
- Written in hexadecimal
- Usually represented as six groups of two hexadecimal digits

Example:

```
00:1A:2B:3C:4D:5E
```

or

```
00-1A-2B-3C-4D-5E
```

---

# 3A.4 Structure of a MAC Address

A MAC address has two logical parts:

### Organizationally Unique Identifier (OUI)

- First 24 bits
- Identifies the manufacturer

### Device Identifier

- Last 24 bits
- Uniquely identifies the interface produced by that manufacturer

Example:

```
00:1A:2B | 3C:4D:5E
^^^^^^^^   ^^^^^^^^^
OUI        Device ID
```

---

# 3A.5 Types of MAC Addresses

### Unicast

Identifies a single network interface.

### Broadcast

The broadcast MAC address is:

```
FF:FF:FF:FF:FF:FF
```

Every device on the local network receives frames sent to this address.

### Multicast

Identifies a specific group of devices that have joined the same multicast group.

---

# 3A.6 Ethernet Frame Structure

An Ethernet frame contains several fields used to deliver data.

| Field | Purpose |
|--------|---------|
| Destination MAC | Identifies the receiving device |
| Source MAC | Identifies the sending device |
| EtherType | Indicates the encapsulated protocol (for example, IPv4 or ARP) |
| Payload | Contains the transmitted data |
| Frame Check Sequence (FCS) | Detects transmission errors |

---

# 3A.7 How a Switch Uses MAC Addresses

When a switch receives an Ethernet frame, it:

1. Reads the source MAC address.
2. Learns which port that MAC address is connected to.
3. Stores the information in its MAC address table (CAM table).
4. Looks up the destination MAC address.
5. Forwards the frame to the correct port if known.
6. Floods the frame to other ports if the destination MAC is unknown.

This learning process allows switches to forward traffic efficiently.

---

# 3A.8 MAC Address Table (CAM Table)

A switch maintains a table that maps MAC addresses to switch ports.

Example:

| MAC Address | Port |
|-------------|------|
| 00:11:22:33:44:55 | Fa0/1 |
| 00:AA:BB:CC:DD:EE | Fa0/5 |

The table is updated dynamically as frames are received.

# Stage 3B – Address Resolution Protocol (ARP)

> Ethernet uses **MAC addresses** to deliver frames on a local network, while applications usually communicate using **IP addresses**. The Address Resolution Protocol (ARP) bridges this gap by allowing a device to discover the MAC address associated with an IPv4 address.

---

# 3B.1 What is ARP?

## Definition

**Address Resolution Protocol (ARP)** is a protocol used to map an **IPv4 address** to a **MAC address** on a Local Area Network (LAN).

When a device knows the destination IPv4 address but does not know the corresponding MAC address, it uses ARP to discover it before sending an Ethernet frame.

Without ARP, communication between devices on the same LAN using IPv4 would not be possible because Ethernet switches forward frames based on MAC addresses.

---

## Why ARP is Needed

Applications communicate using IP addresses.

Switches forward traffic using MAC addresses.

This creates a problem:

```
PC A knows:

Destination IP:
192.168.1.20

But does NOT know:

Destination MAC:
??
```

Before communication can begin, the MAC address must be discovered.

ARP solves this problem.

---

# 3B.2 How ARP Works

Suppose:

```
PC A
IP: 192.168.1.10

Needs to communicate with

PC B
IP: 192.168.1.20
```

PC A performs the following steps:

### Step 1

Checks its ARP Cache.

If the MAC address already exists, communication begins immediately.

---

### Step 2

If the MAC address is not found, PC A sends an ARP Request.

---

### Step 3

The ARP Request is sent as a Broadcast.

Destination MAC:

```
FF:FF:FF:FF:FF:FF
```

Every device on the LAN receives the request.

---

### Step 4

Every device checks the requested IP address.

Only the device with:

```
192.168.1.20
```

responds.

---

### Step 5

PC B sends an ARP Reply.

The reply contains:

```
IP Address

192.168.1.20

MAC Address

00:11:22:33:44:55
```

Unlike the request, the ARP Reply is sent as a **unicast** directly back to PC A.

---

### Step 6

PC A stores the information in its ARP Cache.

Future communication can now occur without repeating the ARP request until the cache entry expires.

---

# 3B.3 ARP Communication Flow

```
PC A
 │
 │ Needs MAC Address
 ▼

ARP Request
(Broadcast)

"Who has 192.168.1.20?"

 ▼

All Devices Receive

 ▼

PC B Responds

"I am 192.168.1.20"

MAC:

00:11:22:33:44:55

 ▼

ARP Reply
(Unicast)

 ▼

PC A Updates ARP Cache

 ▼

Normal Communication Begins
```

---

# 3B.4 ARP Cache

## Definition

The **ARP Cache** is a temporary table stored in a device's memory that contains recently learned IP-to-MAC address mappings.

Example:

| IP Address | MAC Address |
|------------|-------------|
| 192.168.1.1 | 00:AA:BB:CC:DD:01 |
| 192.168.1.20 | 00:11:22:33:44:55 |

Using the cache reduces unnecessary ARP broadcasts and improves network efficiency.

---

# 3B.5 Types of ARP Messages

## ARP Request

Characteristics:

- Broadcast
- Sent to all devices on the local network
- Used to discover a MAC address

Destination MAC:

```
FF:FF:FF:FF:FF:FF
```

---

## ARP Reply

Characteristics:

- Unicast
- Sent only to the requesting device
- Contains the requested MAC address

---

# 3B.6 Broadcast vs Unicast in ARP

| Message | Communication Type |
|----------|--------------------|
| ARP Request | Broadcast |
| ARP Reply | Unicast |

Remember:

Only the request is broadcast.

The reply is sent directly to the requester.

# 3B.9 Security Considerations

✔ Applications use IP addresses.

✔ Ethernet communication uses MAC addresses.

✔ ARP links the two together on IPv4 local networks.

Another common misconception:

❌ ARP works across the Internet.

Correct understanding:

✔ ARP operates only within the local broadcast domain.

Routers do not forward ARP broadcasts between networks.

# Stage 3C – Transport Protocols (TCP & UDP)

> The Transport Layer (Layer 4 of the OSI Model) is responsible for end-to-end communication between applications running on different devices. It ensures that data reaches the correct application using port numbers and provides either reliable or fast delivery depending on the protocol in use.

---

# 3C.1 What is the Transport Layer?

## Definition

The **Transport Layer** is Layer 4 of the OSI Model.

Its primary responsibility is to provide communication between applications running on different hosts.

Unlike the Network Layer, which delivers packets to the correct device, the Transport Layer delivers data to the correct application on that device.

---

## Responsibilities of the Transport Layer

The Transport Layer performs several important functions:

- Segmentation of data
- Reassembly of received data
- End-to-end communication
- Error detection
- Reliable delivery (TCP)
- Fast delivery (UDP)
- Flow control
- Multiplexing using port numbers

---

# 3C.2 TCP vs UDP

The two transport layer protocols are:

- Transmission Control Protocol (TCP)
- User Datagram Protocol (UDP)

Both perform data transport but are designed for different purposes.

---

# 3C.3 Transmission Control Protocol (TCP)

## Definition

TCP is a **connection-oriented** transport protocol that provides reliable communication between devices.

Before data is transmitted, TCP establishes a connection between the sender and receiver.

TCP guarantees:

- Ordered delivery
- Reliable delivery
- Error checking
- Retransmission of lost data

---

## Characteristics of TCP

- Connection-oriented
- Reliable
- Uses acknowledgments
- Detects lost packets
- Retransmits missing data
- Maintains packet order
- Performs flow control
- Performs congestion control

---

## TCP Three-Way Handshake

Before communication begins, TCP establishes a connection.

### Step 1

Client sends

```
SYN
```

Meaning:

"I want to communicate."

---

### Step 2

Server responds

```
SYN-ACK
```

Meaning:

"I received your request and I'm ready."

---

### Step 3

Client responds

```
ACK
```

Meaning:

"Connection established."

The connection is now ready for data transfer.

---

## TCP Session Diagram

```
Client                     Server

  SYN  -------------------->

       <---------------- SYN + ACK

  ACK -------------------->

Connection Established
```

---

# 3C.4 Reliable Delivery

TCP guarantees reliable communication by using:

- Sequence Numbers
- Acknowledgments (ACKs)
- Retransmissions
- Checksums

If a packet is lost, TCP automatically retransmits it.

---

# 3C.5 Flow Control

Flow control prevents a fast sender from overwhelming a slow receiver.

The receiving device advertises how much data it can accept before requiring more.

This helps prevent data loss caused by overflowing buffers.

---

# 3C.6 Congestion Control

TCP also monitors network congestion.

If the network becomes congested, TCP reduces its transmission rate to improve stability and reduce packet loss.

---

# 3C.7 User Datagram Protocol (UDP)

## Definition

UDP is a **connectionless** transport protocol.

Unlike TCP, UDP does not establish a connection before transmitting data.

It sends data immediately without waiting for acknowledgments.

---

## Characteristics of UDP

- Connectionless
- Very fast
- Low overhead
- No acknowledgments
- No retransmissions
- No guaranteed delivery
- No packet ordering

---

## UDP Communication

```
Sender --------------------> Receiver

Data Sent

No Handshake

No ACK

No Retransmission
```

---

# 3C.8 Why Use UDP?

Although UDP does not guarantee delivery, it is ideal when speed is more important than reliability.

Examples include:

- Live video streaming
- Voice over IP (VoIP)
- Online gaming
- DNS queries
- DHCP

In these situations, losing a small amount of data is often less noticeable than delays caused by retransmissions.

---

# 3C.9 TCP vs UDP Comparison

| Feature | TCP | UDP |
|---------|-----|-----|
| Connection | Connection-Oriented | Connectionless |
| Reliability | Yes | No |
| Packet Ordering | Yes | No |
| Acknowledgments | Yes | No |
| Retransmission | Yes | No |
| Speed | Slower | Faster |
| Overhead | Higher | Lower |
| Error Recovery | Yes | No |

---

| Application | Purpose |
|-------------|---------|
| HTTP | Web browsing |
| HTTPS | Secure web browsing |
| SSH | Secure remote access |
| FTP | File transfer |
| SMTP | Sending email |
| IMAP | Receiving email |
| POP3 | Receiving email |

---

## UDP Applications

| Application | Purpose |
|-------------|---------|
| DNS | Name resolution |

| TFTP | Lightweight file transfer |
| VoIP | Voice communication |
| Video Streaming | Live media |
| Online Gaming | Real-time communication |

---

Transport layer protocols use **port numbers** to identify the correct application.

Example:

```

↓

```

Without ports, a device would not know which application should receive incoming data.

# 3C.13 Cybersecurity Relevance

Understanding TCP and UDP is essential for cybersecurity professionals.

- Malware investigations
- Digital forensics

---

# 3C.14 Common Mistakes

❌ "TCP is always better."

Correct:

TCP is more reliable, but not always the best choice. Applications that require speed often use UDP.

---

❌ "UDP is unreliable, so it is useless."

Correct:

UDP is essential for many real-time applications where low latency is more important than guaranteed delivery.

---

❌ "TCP and UDP use the same communication method."

## Stage 3C Summary

The Transport Layer provides end-to-end communication between applications using TCP and UDP. TCP offers reliable, ordered, and error-checked communication through connection establishment, acknowledgments, and retransmissions. UDP prioritizes speed and low overhead by transmitting data without establishing a connection or guaranteeing delivery. Selecting the appropriate protocol depends on the requirements of the application, balancing reliability against performance.

# Stage 3E – Complete Packet Journey

> This section follows the complete journey of a packet from a user's computer to a web server and back again. It combines the concepts of Ethernet, ARP, IP addressing, DNS, TCP, HTTPS, switches, routers, and the OSI Model into one complete communication process.

---

# 3E.1 Scenario

Suppose a user opens a web browser and enters:

```
https://www.google.com
```

Before the webpage appears, many networking processes occur automatically.

The simplified network looks like this:

```
+--------+      +---------+      +---------+      +-------------+
|   PC   | ---> | Switch  | ---> | Router  | ---> |   Internet  |
+--------+      +---------+      +---------+      +-------------+
                                                         |
                                                         |
                                                 +----------------+
                                                 | Google Server  |
                                                 +----------------+
```

---

# 3E.2 Step 1 – User Requests a Website

The user enters:

```
https://www.google.com
```

The browser now needs to discover the IP address of Google's web server.

At this point, it only knows the domain name.

---

# 3E.3 Step 2 – DNS Lookup

The computer sends a DNS request.

DNS translates:

```
www.google.com
```

into an IP address.

Example:

```
142.250.xxx.xxx
```

Protocol:

```
DNS
```

Port:

```
53
```

Transport:

```
UDP
```

Now the computer knows the destination IP address.

---

# 3E.4 Step 3 – Determine Whether the Destination Is Local

The computer compares:

My Network

```
192.168.1.0/24
```

Destination

```
142.250.xxx.xxx
```

Because the destination is outside the local network, the packet must be sent to the **default gateway** (the router).

---

# 3E.5 Step 4 – ARP Resolves the Gateway's MAC Address

The computer knows the router's IP address.

Example:

```
192.168.1.1
```

However, Ethernet requires the router's MAC address.

The computer checks its ARP cache.

If the MAC address is not present:

- An ARP Request is broadcast.
- The router sends an ARP Reply.
- The router's MAC address is stored in the ARP cache.

---

# 3E.6 Step 5 – TCP Connection

HTTPS uses TCP.

Before any web data is exchanged, a TCP connection is established.

Three-Way Handshake:

```
Client ---- SYN ---->

Client <--- SYN-ACK --

Client ---- ACK ---->
```

The connection is now established.

---

# 3E.7 Step 6 – HTTPS Encryption

Because the website uses HTTPS:

```
Port 443
```

TLS encryption begins.

This protects:

- Passwords
- Banking information
- Cookies
- Personal data
- Session information

The communication is now encrypted.

---

# 3E.8 Step 7 – Encapsulation

Each layer of the TCP/IP stack adds its own information.

```
Application Data

↓

TCP Segment

↓

IP Packet

↓

Ethernet Frame

↓

Bits
```

This process is called **encapsulation**.

---

# 3E.9 Step 8 – Switch Forwards the Frame

The Ethernet frame reaches the switch.

The switch:

- Reads the destination MAC address.
- Looks in its MAC address table.
- Forwards the frame out the correct port toward the router.

The switch does **not** examine the destination IP address.

---

# 3E.10 Step 9 – Router Routes the Packet

The router receives the Ethernet frame.

The router:

- Removes the Layer 2 Ethernet header.
- Reads the destination IP address.
- Looks up the best route in its routing table.
- Creates a new Ethernet frame for the next network.
- Forwards the packet toward the Internet.

This process repeats across multiple routers until the destination network is reached.

---

# 3E.11 Step 10 – The Web Server Responds

Google's server receives the request.

The server:

- Processes the request.
- Generates the webpage.
- Sends the response back to the client.

The response follows the reverse path through the Internet.

---

# 3E.12 Step 11 – Decapsulation

As the data reaches the user's computer:

- The Physical Layer receives the bits.
- The Data Link Layer processes the Ethernet frame.
- The Network Layer processes the IP packet.
- The Transport Layer processes the TCP segment.
- The Application Layer delivers the webpage to the browser.

This reverse process is called **decapsulation**.

---

# 3E.13 Complete Communication Flow

```
User

↓

Browser

↓

DNS Lookup

↓

ARP

↓

TCP Handshake

↓

TLS Encryption

↓

Encapsulation

↓

Switch

↓

Router

↓

Internet

↓

Google Server

↓

Internet

↓

Router

↓

Switch

↓

Decapsulation

↓

Browser Displays Webpage
```

---

# 3E.14 Where Each Protocol Is Used

| Protocol | Purpose |
|----------|---------|
| DNS | Resolves the domain name to an IP address |
| ARP | Finds the MAC address of the default gateway |
| Ethernet | Delivers frames on the local network |
| IP | Routes packets across networks |
| TCP | Establishes a reliable connection |
| TLS | Encrypts HTTPS communication |
| HTTPS | Transfers secure web content |

---

# 3E.16 Troubleshooting Example

Suppose a webpage does not load.

A network administrator might check:

1. Is the computer connected to the network?
2. Does it have a valid IP address?
3. Is the default gateway reachable?
4. Is DNS resolving the domain name?
5. Is the TCP connection established?
6. Is the firewall blocking traffic?
7. Is the destination server online?

Following the packet journey step by step helps isolate where communication is failing.
